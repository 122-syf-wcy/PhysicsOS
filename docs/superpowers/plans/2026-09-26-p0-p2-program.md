# PhysicsOS P0-P2 Completion Program

> Use the named task briefs as the implementation contract. Keep each task's
> write set disjoint. The controller owns shared registries, bundle wiring,
> overlay capture, and the final cross-task review.

**Goal:** Close every currently identified P0-P2 product, data, deployment,
and maintenance gap without replacing the shipped physics architecture.

**Global constraints:**

- Preserve the existing PhysicsOS -> Harness overlay boundary. PhysicsOS-owned
  files are edited under `overlays/harness/files/**`; upstream behavior changes
  are edited in `vendor/deepseek-harness/**` and captured into
  `overlays/harness/upstream-changes.patch`.
- Never claim success without a fresh command and output.
- Do not remove or rewrite another task's files to resolve a conflict.
- All new external calls fail closed, use bounded inputs, and expose actionable
  errors.
- No UI control may remain permanently disabled without a test proving why.
- Use TDD for behavior changes and add composition-level coverage for new hosts.

## Task 1: Production deployment and root CI

**Write set:** root `.github/**`, `Dockerfile`, `.dockerignore`,
`compose.yml`, `scripts/healthcheck.mjs`, `docs/13-DEPLOYMENT-OPERATIONS.md`,
and a new `overlays/harness/files/packages/physicsos/health-host/**`.

**Deliverable:** Root CI for install/format/typecheck/lint/tests/build;
multi-stage app image; Compose with app, PostgreSQL, Redis, healthchecks,
volumes, and secret-file wiring; `/healthz` and `/readyz` host plugin with
unit/composition tests; deployment, backup, restore, and rollback runbook.

## Task 2: Account lifecycle and shared runtime state

**Write set:** `overlays/harness/files/packages/physicsos/auth-host/**` and
the auth-specific client files
`AuthGate.tsx`, `auth-api.ts`, `auth-store.ts`, and `locales.ts`.

**Deliverable:** One-time password-reset token flow with hashed token storage,
expiry, rate limits, invalidation, delivery adapter seam, and admin queue/UI;
ownership migration command for legacy sessions/workspaces; shared limiter
seam with an in-memory reference backend and documented Redis implementation
boundary.

## Task 3: Server-side personal learning and scene sync

**Write set:** new
`overlays/harness/files/packages/physicsos/learning-host/**`, plus
`learning-record-store.ts`, `surface-store.ts`, and new `learning-api.ts`
under the same client package.

**Deliverable:** Authenticated `/physicsos/learning` host storing personal
attempts and saved scenes per account with tenant checks, pagination,
idempotent writes, and cross-device reads; client compatibility/migration from
localStorage; aggregate reporting remains privacy-preserving and separate.

## Task 4: Class, assignment, and teaching workflow

**Write set:** new
`overlays/harness/files/packages/physicsos/class-host/**` and new client
`class-api.ts` plus teacher/student class surfaces.

**Deliverable:** Tenant-scoped classes, membership by `userKey`, assignments
linking a paper or experiment, due dates, student submission/receipt,
teacher review, and per-class completion dashboard with role enforcement.

## Task 5: Physics content expansion

**Write set:** `packages/engine-wave/**`,
`packages/engine-modern/**`, `packages/engine-composite/**`,
`packages/physics-scene/**`, `packages/question-core/**`, and the
corresponding client physics runtime/template files.

**Deliverable:** Verified time-varying-field cyclotron model; longitudinal
wave, reflection/refraction, diffraction, and Doppler models; a modern-physics
vertical slice with engine, scene, verifier/observation, question fixtures,
and experiment templates. Unsupported cases must return `UNSUPPORTED_MODEL`.

## Task 6: Desktop shell and signed update client

**Write set:** `apps/desktop/**`, `packages/platform-bridge/**`,
`packages/agent-dsh-adapter/**`, and desktop release scripts.

**Deliverable:** Buildable Tauri development shell, platform bridge
implementations for device/update/storage, signed-update verification path,
local sidecar transport, build scripts, and unsigned local packaging tests.
Certificate-dependent notarization/publish steps remain configuration, not
unimplemented code.

## Task 7: Engineering debt and documentation reconciliation

**Write set:** root `package.json`, `pnpm-workspace.yaml`, package invariant
scripts/config, README/backlog/handover files, and legacy skeleton packages.

**Deliverable:** Root constraints/invariants pass, dependency audit path is
documented and runnable with the configured registry, obsolete skeleton
packages are implemented or retired, and current feature status is reflected
in README/backlog/handover.

## Integration and final acceptance

- Controller grants each task a disjoint write set and resolves shared bundle
  wiring after implementers return.
- Each task must include focused tests and a concise implementation report.
- Run root typecheck/lint/test/build, host composition tests, browser
  acceptance, overlay apply/capture idempotence, and a final independent
  code review before declaring the program complete.
