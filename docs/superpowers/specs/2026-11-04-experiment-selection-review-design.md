# 实验上传选择与后台审核入口

用户要求上传时选择对应实验，并在管理后台直接审核和渲染上传的实验。当前审核和沙箱三维预览已经存在于上传页；后台缺少入口，上传的目标也隐含为凸透镜。

沿用已有上传规范和渲染契约。上传页增加液态玻璃“对应实验”下拉框，从已有实验目录显示名称；注册了上传契约的凸透镜可选择，其余明确标记尚未开放。所选目标明确传入上传、目录和回滚 API；服务端仍校验 ZIP 中的 experimentId，避免把错误实验映射进凸透镜。是否同时开放其他契约已向用户询问，在答复前按此前确认的凸透镜范围推进。

管理后台内容组新增仅平台管理员可见的“实验审核”。复用 ContributionPanel 的 review 模式，去掉上传表单和开发资源链接，增加状态筛选和数量；实际加载冻结上传包，通过独立物理条件与沙箱渲染检查，再执行通过/退回/回滚。渲染失败不能通过审核。

选择显式目标和复用审核组件可保持现有安全/物理实现一致。另起一套后台渲染或仅放通其他 ID 都会造成契约不一致，因此本轮不采用。所有构建/测试/候选/部署在 107.151.246.59 Docker；沿用用户已授权的 GitHub/正式部署，保留版本和恢复点。


## 用户确认扩展全部实验

用户明确要求全部已有实验。范围更新为 76 个实验全部可上传。采用新增通用 V3 协议：现有实验目录生成 canonical id/domain/参数和选择项；ZIP 清单必须与所选注册实验匹配；参数/引用资源有边界校验，平台计算物理结果，上传作品只消费只读的视觉快照。V3 MessagePort 首帧渲染确认与错误状态用于辅助管理员审核。

新默认 SDK 内置官方只读 PhysicsCanvas，覆盖全部实验；开发者可改为 Three/canvas 自定义展示。目标模板和开发提示词按实验生成，保持 V1/V2 凸透镜存量兼容。后台跨实验审核队列有状态及实验筛选，实际加载 ZIP 作品，发布/回滚只改变该实验的默认版本。通用实验工作区采用同一物理运行时和控制面板展示被批准的作品，并绑定已保存的发布版本。

后台、渲染/自动显示、模板生成三个独立子任务并行，主实现者负责共享契约、上传选择、后台过滤和全链路验收。所有76注册/模板验收及典型域的真实浏览器测试在服务器 Docker 完成，再按既有流程备份、候选、正式部署和 GitHub 提交。
