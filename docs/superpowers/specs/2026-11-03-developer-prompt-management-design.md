# 开发提示词后台管理

用户要求后台修改提示词、设定版本、上传并修改 Markdown；已确认“保存草稿，手动发布”。本轮接续已完成的凸透镜 V2 投稿流程，沿用独立工作区及 107.151.246.59 Docker 验证，不部署生产。

## 方案与范围

采用服务器保存提示词版本、后台管理、开发者页读取当前发布版。修改源码中的静态提示词会要求重建主站，不符合后台运营需求；直接覆盖当前内容会让草稿影响开发者，也违背用户选择。故选用一个草稿 + 不可变发布历史 + 当前版本指针。

后台在“内容”组增加 SUPER_ADMIN 专属“开发提示词”页，首期只管理 convex-lens 的实验开发提示词，不扩展模型系统提示词或新实验注册。已有液态玻璃控件复用。服务器同时限制后台读取和写入，学校管理员和普通用户不能读取草稿。

## 编辑与 Markdown

- 一个实验保留一个共享草稿，可修改 Markdown 正文、提示词版本及修改说明。版本为无前导零的 X.Y.Z，最长 32 字符，与实验包版本、schemaVersion 独立。已发布版本号不可再次使用。
- 默认编辑内容来自现有提示词的可运营说明；固定实验协议、模板真实摘要和 release 要求由系统补入，不接受管理员修改协议本身。允许修改现有风格/教学/开发建议，而不只是追加文字。
- 后台展示当前版本、草稿、版本历史以及完整提示词预览。复制/下载完整提示词与开发者页使用同一个格式化模块。
- 支持选择 .md/.markdown 导入草稿，导入后继续编辑。普通 Markdown 当作正文；平台导出的完整 Markdown 用明确的 editable 标记提取正文，固定契约区不作为可编辑正文重新导入。重复/残缺标记报错。导出携带版本信息，导入版本由界面可明确修改，不暗中覆盖已发布内容。
- 正文最多 64 KiB UTF-8；上传文件最多 128 KiB，拒绝无效 UTF-8、NUL/不允许控制字符、非 Markdown 扩展名。接受 UTF-8 BOM/CRLF 并规范化为无 BOM/LF。文件名仅作输入校验，不写入任意服务器路径。
- Markdown 展示为安全文本/现有安全 Markdown 组件，不执行上传 HTML、脚本、模板表达式或远程代码。

## 发布、并发与绑定

- 保存、导入、发布、切换版本均携带服务器状态 revision；过期请求返回 409，保留浏览器未保存文字并明确提示刷新，防止多管理员覆盖。
- 发布冻结正文、版本、修改说明、操作者、时间、固定规范和当时的模板描述符。服务端生成内容摘要及版本 ID；审批/选择版本以 ID 与摘要绑定，不能只按版本字符串猜测。
- 新草稿保存时绑定当前部署的规范/模板；从历史正文继续编辑属于新草稿，发布绑定当前规范。若保存后部署的规范/模板改变，发布拒绝陈旧绑定并要求重新保存预览。
- 草稿成功发布后清空草稿，并原子更新当前指针；失败不改变现有发布版。切换到历史版本保留全部历史，不覆盖历史正文。
- 提示词状态使用独立 storage-domain，随既有存储持久化；不混入大实验包状态。沿用单进程服务写队列与一次状态行写入，写成功后才更新内存状态。最多 200 个发布版、1000 次切换记录，达到上限明确拒绝，不自动删除历史。
- 初始没有后台记录时提供现有规范生成的默认提示词，标记“系统默认”；不伪造管理员发布记录。

## 开发者同步

开发者文档从同源公开接口读取已发布的提示词及其冻结模板绑定。正文版本/摘要明确展示；复制、完整预览和 Markdown 下载一致。保存草稿不改变接口内容，发布/回滚后重新加载页面获得相应版本，无需主站重建。

公开接口只暴露已发布内容与必要元数据，不暴露草稿、操作者账号或内部存储信息。当前版本不缓存；历史版可以按不可变 ID 读取，仍只允许读取发布记录。模板 URL 继续使用 digest 文件名，绑定旧模板的提示词保留相应旧 URL。

读取失败不静默回退成旧提示词；普通文档仍可阅读，绑定复制/下载暂时禁用，提供重试并保留任务输入。实际提示词中的模板 URL 按当前站点来源解析，与之前候选/正式来源规则一致。

原 V2 模板及其 ZIP 摘要保持不变。后台管理的是外部任务提示词版本，不修改或重新打包已冻结 SDK/模板。系统生成的固定规范说明外部当前提示词的可编辑说明优先于模板中的初始运营说明；机器格式契约不受影响。

## 技术边界与验收

复用 experiment-host 的身份、CSRF、错误与审计模式，新增独立 prompt service/routes/domain。受保护接口不能沿用“GET 只需登录”的宽松默认，必须明确检查 SUPER_ADMIN。公开路由与后台路由分开。所有写入记录操作者与发布/切换事件，审计不记录正文。

共同的纯格式化模块处理 editable 标记、完整 Markdown 和固定绑定；默认 seed 从现有规范及实际 template-release.json 生成，不维护第二套手写协议。生成检查验证副本/seed 一致，普通 prompt 内容发布不修改仓库。

验收覆盖草稿不生效、版本唯一性、并发 409、发布冻结、历史回滚、重启持久化、权限/CSRF、过期模板绑定、UTF-8/文件大小/标记边界、公开无草稿泄露；真实浏览器从后台导入 MD→编辑→保存→发布→开发者复制/下载→回滚，比较全部文本并验证桌面/手机与失败恢复。复用既有独立候选账号和 Docker；不重跑已完成的实验上传/物理验收，除非本轮代码出现相关风险。

实现细节由代理确定并记录：共享草稿而非多人独立草稿，标准版本号约束，保留历史上限，单进程原子写队列。若未来横向部署多个写入实例，需要另行提供存储级 CAS；本轮不声称具备多进程写隔离。
