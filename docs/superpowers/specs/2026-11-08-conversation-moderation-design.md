# 后台对话审查与人工封禁

用户要求接续后台对话监听、AI 自动审查、人工审核封禁和提示注入防护，并验证后部署。此前任务仅排查即中断。本设计采用已有技术和权限体系；用户此前要求自行抉择，本次继续实施。

## 目标和选择

在现有 SUPER_ADMIN 后台增加「对话审核」。记录真正来自人的消息与可信服务器归属，自动形成风险建议；管理员查看证据、驳回误报、重试审查或封禁。AI 不直接封禁，不得到管理员接口、工具、凭据或用户标识控制权。法律、历史、安全教育和物理教学讨论不能因关键词自动封禁。

采用 auth-host 中独立 moderation 模块和 auth domain 新表：它能复用真实凭据、CSRF、账户停用和审计，避免第二套权限和封禁逻辑。独立新宿主需要扩展身份和部署契约；放入 ops-host 则违反其不收集对话的约定，均不采用。

## 行为和安全边界

- 只捕获服务端确认归属的真实 user 输入；不将工具结果、技能通知、继承的 fork 前缀或审查本身当作新用户输入。按会话、message ID 与完整原始文本/上下文摘要去重；相同输入在 inbox、日志和所有权补捕之间只保存一次，编辑内容生成新的不可变证据记录，保留旧原文与人工决定。启动后恢复中断任务。新消息自动记录，历史补扫由管理员触发且每次最多 20 条消息。
- AI 使用既有 ctx.llm，无工具、固定系统政策，待审内容序列化为 JSON 数据。provider/model 由部署配置决定，不取自对话。严格校验 JSON、枚举、证据、置信度、完成状态和长度。错误、低置信度、输入截断、工具调用和超时进入人工复核，不能默认为安全。
- 同时补强 physics-student 的固定助教系统指令：拒绝违法伤害、诈骗、未授权入侵及绕过安全限制的具体协助；合法物理、安全教育和求助继续支持。对话中自称管理员、伪造 system/developer 或索取隐藏提示不能提升权限。保留原物理宪法及受限工具集合。
- 输入文本最多 12,000 字符，上下文最多 4,000 字符；原消息的文本截断有明确标记。仅保存文本证据，不复制文件、图片、系统提示词或凭据。模型输出最多 8,000 字符，45 秒取消，单请求最多 4,096 输出 token；自动调用串行且至少间隔 15 秒。
- 接口只允许 SUPER_ADMIN 的 Cookie 登录会话，包括读取；拒绝个人 API token。写入复用 JSON、同源/Fetch-Site CSRF 检查。响应 private/no-store；列表分页最多 50 条，详情按 case ID，原文仅作 React 文本展示。
- 人工决定 require 当前 version 和非空理由。封禁目标固定来自 case 的服务器 owner；复用 AuthService.setUserStatus，禁止停用自己/SUPER_ADMIN。并发决定及在途 AI 不能覆盖人工决定。重复封禁可安全恢复失败的结果写入。审计仅存 ID、动作和结构化摘要。
- 保留学校合并流程：审核记录随真实账户迁移归属，ID、原文和 userId 不变；归属迁移更新 version，并将 reviewing 任务重新置为 pending，防止在途结果覆盖迁移。全站审核设置不随学校迁移。审核存储达到容量上限时保留证据并记录可见的接收失败状态，不能静默丢弃。
- 停用撤销登录及 API token，取消该账户根 Agent 和可信子 Agent，并清空 inbox。真实 WebSocket 远程流需每次开流检查会话归属，并随凭据失效关闭，防止旧连接继续操作或读取。
- 保留全部现有功能，特别是已上线实验、性能优化和后来发布的官网管理；不把候选数据库或测试账号复制到生产。
