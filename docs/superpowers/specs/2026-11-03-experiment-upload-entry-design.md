# 实验上传入口接通

用户在正式站点找不到已实现的实验上传，希望检查既有方向并优化。核对结果：远端 main 与正式容器仍为33023a2，上传 API 返回404；开发分支2304ad1已包含完整闭环，主工作区另有未提交的 ContributeWorkspace 介绍页，上传/审核仍显示待接入。

沿用已确认的独立 ZIP、平台引擎、隔离预览、SUPER_ADMIN 审核、最新通过版用于新会话的架构。优化入口发现和已有代码整合，不重做宿主，不扩大支持的实验。

## 方式与实现判断

仅保留凸透镜页按钮最省改动，但贡献者必须先打开实验才能投稿；只把旧贡献介绍页加入菜单仍然不能上传。本轮采用统一“实验上传”页，复用现有 ContributionPanel 的表单/记录/审核内容，保留实验页弹窗。这个入口选择是实现判断，用户已授权沿现有方向优化。

## 行为

- 侧栏“实验上传”、实验中心入口及 `/#/contribute` 均进入统一页面。页面保留旧贡献页的图标、语义样式和独立文件投稿说明，直接展示真实上传表单。
- 明确当前支持“凸透镜成像规律”，不提供不可用的实验选项。保留模板、规范及打开对应实验的链接。
- 页面与原弹窗使用同一上传/版本/审核实现和 API。页面不使用 aria-modal、焦点陷阱或背景遮罩；原实验弹窗保留关闭、焦点恢复和隔离预览。
- 页面导航、浏览器历史/刷新不丢失已打开的实验及记录。上传后的状态取服务器真实响应；401/404或非JSON失败显示明确错误，允许重试，不报告假成功。
- 不改变角色、文件限制、公开资源边界和发布规则。原工作区其他题目/试卷改动保持原样，只将既有贡献入口部分整合至开发分支。

## 验证与发布

用户补充视觉要求：原生 Choose File 控件过于简陋，上传区按钮使用液态玻璃风格。复用平台现有玻璃材质 token，美化选择、更换、移除、下载和提交动作；保留真实 file input，由中文可访问按钮触发，显示已选文件名及大小。输入框与表单使用同一材质，保持暗色、手机、键盘焦点与减少动态效果设置可用。只调整当前上传界面，不改变文件权限、限制和审核流程。
