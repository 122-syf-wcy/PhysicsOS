# 开发者界面视觉统一与发布

用户要求整体美化本轮新增界面的原生按钮和布局，并部署正式站点、提交 GitHub。沿用已确认的液态玻璃风格和草稿/手动发布流程。

## 方案

采用现有 React、CSS Modules 与玻璃材质变量：提示词后台改为清晰的发布概览、编辑/预览工作区及历史列表；Markdown 导入用带图标的中文按钮触发原生文件选择器；所有主要操作统一高度、材质、焦点与禁用状态。上传页强化准备资源、上传表单、审核记录的层次；公开开发者页统一玻璃按钮、表单与代码预览。手机使用单列和可换行工具栏。

只改按钮颜色不足以解决用户指出的排版问题；更换组件库则会增加不必要的依赖与回归面。因此在现有组件上调整结构和样式。具体尺寸与间距由实现者确定，真实浏览器截图验收。

## 边界与发布

- 不改 API、上传格式、权限、草稿发布语义和冻结模板；已有验收覆盖交互，视觉变化以桌面/手机/深色截图和焦点检查验证，不编写仅复述 CSS 的单元测试。
- 在既有隔离工作区开发，所有构建/测试在 `107.151.246.59` 的 Docker 中执行。
- 发布前核对 GitHub main、服务器源码与运行镜像；保留现网后续功能、切换前镜像、数据库和文件恢复点。
- 用户本轮已授权 GitHub 提交和正式部署。候选验证后执行，不重复请求许可。密钥只从既有文件/挂载读取，日志和提交不含凭据。
