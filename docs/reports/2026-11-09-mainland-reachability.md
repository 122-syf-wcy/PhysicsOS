# 中国大陆访问可达性排查（2026-11-09）

结论：已复现**部分电信路径的间歇性慢连接和超时**，同时联通、移动及校园网存在正常访问。现有证据不支持“全网不可达”，也不足以认定 IP 或域名被统一封锁。

用户反馈至少 8 位老师直连无法打开，部分使用代理后可打开，随后确认校园网可以访问。本轮只读排查，未修改 DNS、Nginx、系统网络参数或购买服务。

## 实测

JS 请求路径为 `/assets/index-CWpY4Fb7.js`。上表合计 19 次有效 GET，16 次返回 200、3 次超时；这是针对性的小样本，不能换算为用户总体成功率。

较早的 5 节点默认 HTTP 探测均返回 200，但成都一次 TLS 握手约 8.96 秒，也显示“能连接”不代表连接稳定。三个 `*-https-retry-results.json` 请求误将 `?` 编入路径成为 `%3F`，其 404 属于探针参数错误，**未计入网站故障**。

同轮服务器检查：应用与 Nginx 没有地域拦截规则；服务器 INPUT 为 ACCEPT；223、119、8.8、1.1 DNS 查询均指向 `107.151.246.59`，无 AAAA；证书有效至 2027-01-25，成功探针的 TLS 校验通过。本机及服务器访问主页、当前入口脚本均为 200。

## 判断与证据边界

同一电信城市有时成功、有时在 TLS 或首字节阶段超时，而同时的联通/移动样本明显更快，运营商到当前服务器的路径差异是目前最有力的线索。尚不能精确区分运营商出口/回程、链路丢包、中间设备、机房上游或部分终端因素，也不能据一次代理成功认定封锁。

三次正确首页请求使用了独立 User-Agent 标记。当前明文 Nginx access 日志未找到这些标记，故本报告**不声称已由服务端日志证明这些特定请求收到或返回 200**；相关关联仍缺证据。没有输出客户 IP、Cookie 或凭据。

HTTP 探针不是受影响老师的真实浏览器，也未验证完整页面执行、登录后的 API 或 WebSocket。入口脚本返回 200 不等于整个应用已可交互；仍缺持续时段样本及失败终端的完整请求链证据。

## 改善建议

1. 优先评估面向国内三网优化的线路或 CDN，以东莞、广州、南京电信作为重点验收路径，同时保留联通/移动对照。先用候选入口比较 DNS、TCP、TLS、首字节和完整页面加载，再决定切换；普通全球 CDN 不保证改善所有电信路径。
2. 优先让带内容哈希的公共 JS/CSS、图片、已发布实验资源命中边缘缓存，减少首次打开所需的跨网请求。插件合并资源必须保留完整查询串作为缓存键。登录、管理员接口、私有数据及 WebSocket 保持正确回源和长连接语义。
3. 若选用中国大陆 CDN 节点，核对供应商要求的域名接入资质；否则比较合适的区域节点或优化回程方案。仍以真实三网及完整产品流程验证结果作为选择依据。
