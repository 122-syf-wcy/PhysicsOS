## Windows 接手顺序

1. 按[Windows 开发说明](../../apps/android/README.md)准备本机工具链，先运行源码预检；不要通过删导航、加空 Screen 或返回假数据来让检查变绿。
2. 补齐原生页面入口和文案资源，保留完整功能与真实接口。
3. 完成独立实验打包链，验证全部真实模板、编辑历史和本地资源，不改成线上整站 WebView。
4. 完成移动 API/宿主原语的接线与契约测试；后端在服务器候选环境验证，Windows 不运行 Linux 专属擦除服务。
5. Windows 执行 Kotlin/资源编译、lint、单元与设备测试，修复真实错误；Mac/服务器执行 Web 与后端回归。
6. 使用受控测试账号进行端到端验证，再在目标入门/中端真机和平板测性能。
7. 完成签名、插件清单重签、旧派生缓存迁移及运营侧隐私/条款审核后，才进入发布审批。
