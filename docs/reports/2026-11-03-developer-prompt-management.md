## 验收中修正的边界

1. 存储写入可能在持久化后才报告错误。失败时恢复上一份持久化记录；恢复仍失败则返回 503、暂停提示词访问，直到存储及服务重新打开后读取有效状态。针对“提交后报错”和恢复失败的测试先失败后通过。
2. JSON/JSONB 不保证对象字段顺序。摘要和草稿绑定按明确的字段顺序计算；重新排列持久化对象及配置对象后，版本摘要和草稿发布保持不变。该回归先复现 `Invalid persisted prompt history`，修复后通过；这不等于已进行生产 PostgreSQL 实测。
3. 手工 JSON 中的孤立 Unicode 代理码元会被 UTF-8 编码器替换。现在正文必须能无损往返 UTF-8；孤立码元被拒绝，正常中文与非 BMP 表情保留。文件导入另有严格 UTF-8 解码。
4. 静态最新模板链接可能与历史提示词的冻结绑定不同。上传页改用当前绑定的无缓存下载入口，公开开发者页仍直接引用当前提示词携带的摘要文件名。
5. 早期元素截图受滚动容器裁切而出现空白；截图改为先滚到页面标题再截取视窗，没有为截图改变布局或放宽功能断言。下载链接统一复用玻璃按钮样式。
6. 审查指出普通 `.trim()` 会改变首行缩进及行尾硬换行，完整 MD 中被丢弃区域的控制字符也可能漏检。现在先检查完整输入，只规范化 BOM/换行编码，保留作者空格和换行；完整导出导入只去掉系统添加的一行边界换行。相应测试由 6 个失败转为全部通过，真实浏览器的保存/发布/下载/再次导入也验证了缩进与换行保真。
7. 公开页明确显示提示词内容摘要，单独区别于模板 ZIP 摘要；说明其根据版本、正文与模板绑定计算。缺失展示的浏览器测试先失败后通过，复制与下载的完整 Markdown 语义保持一致。

## 设计取舍与限制

| 决定 | 理由及可能成本 |
| --- | --- |
| 用户确认草稿/发布方式后直接实施，不再重复请求计划确认 | 范围明确且源码修改可逆；若对具体交互理解不同，成本为可逆返工。 |
| 一个共享草稿、独立 X.Y.Z 提示词版本 | 适合当前后台运营，revision 防止同进程多管理员覆盖；不提供每人独立草稿。 |
| 正文 64 KiB、导入 128 KiB、200 个发布版、1000 条发布/切换记录 | 有界存储且不自动删除历史；达到上限需后续维护方案。 |
| 外部提示词版本与 V2 模板分开，固定规范由系统补入 | 后台发布无需重建主站，既有 SDK/ZIP 不变；模板初始开发说明与后台说明不同时，完整提示词明确说明优先关系。 |
| 采用实际 storage-domain 的 `put` API | 修正计划中假设的 `set` 名称，行为仍为一次完整状态写入。 |
| 写入异常时恢复旧状态，无法恢复则拒绝访问 | 不把不确定的缓存视为成功发布；连续存储故障需要服务/存储重启与核对。 |
| 公开当前/历史 Markdown，旧 AGENTS.md 地址动态响应 | 避免旧书签获得构建时提示词；只公开已发布投影，不公开后台资料。 |
| 上传页下载入口跟随当前冻结模板绑定 | 避免回滚后模板与提示词不匹配；已经复制的提示词仍携带其自身不可变 URL。 |
| 对绑定字段进行固定顺序序列化 | 兼容 JSONB 等存储的键序变化，保持已发布内容摘要稳定。 |
| 保留作者空格与换行，仅规范化 BOM/换行编码 | Markdown 的缩进和行尾空格有语义；完整文件导入只剥离系统边界换行，额外空白由作者保留。 |
| 一轮完成审查提出的三项既定要求 | 这些属于输入保真、全文件校验和版本标识，没有扩展新功能；成本是一次额外的定向修正与验证。 |

此实现使用单进程写队列与 revision 检查。若横向部署多个写入进程，需先增加存储级 CAS/事务协调。候选使用 JSON 存储，未操作生产 PostgreSQL。现有 Vite 大块/插件计时、跨平台可选包、Node 实验性类型剥离提示属于已知构建信息，不代表全仓库零警告或安全认证。

此前 V2 开发包的完整验收与审查已完成，本轮不重复其物理实验/ZIP 发布测试，也不扩展到全新实验、所有模型提示词或生产发布。最终独立审查仅覆盖本轮 `6555882` 之后的变更及其具体集成边界。
