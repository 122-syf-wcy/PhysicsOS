# 物理与状态

代码风格的核心，也包括“谁有权决定这个数字”。

## 唯一事实源

PhysicsScene Runtime 保存已提交的物理条件；引擎生成结果与校验。React、Three Object3D、图表和助教只展示或解释它们，不能各自维护一套质量、速度、焦距或时间。

### 一条状态链

```text
参数操作 / 器材拖动
  → 场景命令与校验
  → 场景修订
  → 引擎结果与可视快照
  → 三维装置、读数、记录、报告
```

## 把预览与提交分开

- pointermove：显示临时预览，不写持久化记录。
- pointerup：提交一次有效命令，产生可追溯的场景修订。
- pointercancel / Escape：恢复上次已提交条件。
- 切换页面与卸载：取消未完成拖动，移除事件。
- 从题目进入实验：变更题面条件时建立实验分支，保留恢复原题入口。

## 单位与时间要明确

计算采用平台单位系统。场景坐标可以采用便于展示的尺度，但转换必须集中在桥接边界，说明原点、方向和比例。不得把显示时间当物理时间，不得通过改变物理结果来追求顺滑动画。

> **三维呈现 ≠ 任意三维求解**：将薄透镜光路放入三维光具座是呈现升级；若改变空间模型或引入新力学自由度，需要扩展求解器和独立验证。

## 验算用例要独立给出

| 条件（cm） | 预期结果 |
| --- | --- |
| f=10，u=30 | v=15；倒立、缩小、实像 |
| f=10，u=20 | v=20；倒立、等大、实像 |
| f=10，u=15 | v=30；倒立、放大、实像 |
| f=10，u=10 | 无有限位置的像；出射光平行 |
| f=10，u=5 | 虚像位于物体同侧；正立放大；光屏不能承接 |

测试期望来自独立参考值或推导，不调用被测函数来计算期望。临界值附近、非法参数与保存恢复同样要检查。
