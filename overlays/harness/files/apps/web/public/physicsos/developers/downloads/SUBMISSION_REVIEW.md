# 提交与审核

让代码、结果和作者一起被看见，也让每一次发布可追溯。

## 当前：通过 Pull Request 贡献

- 从最新 main 创建聚焦的贡献分支。
- 提交源码与资料，运行对应检查，附清楚的变更说明。
- 包含典型/边界用例、桌面/手机截图与限制说明。
- 由维护者评审，CI 通过后整合；不要自行绕过生产发布流程。

### 正式 Web 检查

```shell
pnpm typecheck:web
pnpm lint:web
pnpm test:web
pnpm build:web
git diff --check
```

这些命令用于完整 PhysicsOS 仓库，不用于下载的独立风格工具包。修改领域引擎时补对应包测试；本机缺少依赖不代表服务器环境不可用。

## 规划：对应实验上传，审核后自动发布

### 计划中的流程

```text
对应实验 → 贡献实验 → 上传 ZIP 与作者资料
  → 自动校验 / 隔离构建
  → 管理员交互预览 / 审核
  → 通过后自动更新默认版本
  → 实验页显示新效果与本次作者
```

最新审核通过的版本直接成为默认效果，不新增普通用户社区版本选择器。历史版本保留作追溯与回滚。发布失败保留旧版；正在运行的实验继续固定原版本。

## 审核需要的证据

| 检查面 | 材料 |
| --- | --- |
| 代码一致性 | 格式、命名、lint、类型检查结果 |
| 物理可信 | 引擎绑定、参考值、临界值、适用模型 |
| 交互 | 拖动提交/取消、键盘/触摸、复位与保存恢复 |
| 三维稳定 | 资源大小、性能数据、重复挂载、context loss |
| 作者与许可 | 署名、GitHub、共同作者、每项素材来源 |

> **独立实验代码需要隔离**：未来投稿在隔离构建和受限实验视图区中运行，通过允许的消息协议调用平台能力。源码不能访问主站凭据、Cookie、其他用户记录或生产数据库。
