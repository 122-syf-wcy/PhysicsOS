# School admission and cleanup

New registration, school applications and direct school creation share school-name admission. Surrounding and repeated whitespace are normalized while the submitted spelling is retained. Lookup and uniqueness use a case-insensitive Unicode compatibility key. Blank, control-only, numeric, email, URL and punctuation-only names are refused; genuine unlisted schools, international names and names containing apostrophes or hyphens remain supported.

School creation, application reuse and approval serialize through the credential mutation queue. A normalized name already belonging to a visible tenant cannot create another tenant through a different id. Legacy invalid or duplicate applications remain pending when approval is refused; approval does not silently move accounts to another school.

An occupied school is never deleted merely because its display name is invalid or duplicated. `canonicalName` changes display only, retaining the original durable `name`. `rosterAliasOf` hides a duplicate roster entry while its school/account keys, credentials and all business data remain intact. `archivedAt` and `archiveReason` retire explicitly reviewed empty tenants, including unregistered roster seeds and known test fixtures; their historical application records remain intact. Existing `mergedInto` identifies a completed ownership migration; it is not used for display-only cleanup. Additive seeding respects retained tombstones. Normal registration search and administrator roster lists exclude retired and alias entries; existing account login resolves its original tenant.

`school-cleanup-audit.ts` generates read-only PostgreSQL queries over explicit table inventories and school candidates. It selects school names, structured ownership references and counts, excluding applicant details, credentials and conversation text. Its SQL starts `BEGIN READ ONLY` and contains no mutation. Production cleanup requires a reviewed exact mapping and paired PostgreSQL/app_data backup; the three-unit JSON merge CLI does not cover the deployed unit inventory or private Canvas blobs.
